**Rebuild rule for rank 7 (derived, not observed in an iOS plist).** The checkout proves three facts: `ConnectToServerViewModel` prepends `http://` when the typed address has no `://` (`Shared/ViewModels/ConnectToServerViewModel.swift:62`); server discovery sends a UDP broadcast to `255.255.255.255:7359` with the payload `who is JellyfinServer?` (`jellyfin-sdk-swift@3.3.0:Sources/ServerDiscovery.swift:41-43`) and is started from `ConnectToServerViewModel.swift:178`; and the only readable plist (tvOS) sets `NSAppTransportSecurity` > `NSAllowsArbitraryLoads = true` and carries no `NSLocalNetworkUsageDescription` or `NSBonjourServices` (`Swiftfin tvOS/Resources/Info.plist:43-47`). From these facts plus Apple platform rules (ATS and the iOS local-network privacy prompt are Apple platform behaviour, not shown by any file in this checkout or the pinned dependencies), an iOS rebuild should set `NSAppTransportSecurity` > `NSAllowsArbitraryLoads = true` to allow plain-`http://` servers, as the tvOS plist does, and an `NSLocalNetworkUsageDescription` string for the discovery broadcast. Whether `NSBonjourServices` is needed, and for which services, the source does not show. The actual iOS values stay unverified because `Swiftfin/Resources/Info.plist` is absent. The in-app permissions screen carries `// TODO: local network permission just with description` (`Views/AppPermissionsView.swift:82`), so the app does not prompt for local network itself.
